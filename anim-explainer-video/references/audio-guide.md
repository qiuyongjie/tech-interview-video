# 配音与字幕指南

配音差通常不是"模型不行"，而是**断句、时间、读音、响度**四件事没做对。管线已经把四件事工程化；写文案和调参时按下列规则。

## 1. 音频先行管线

```
旁白逐句定稿 → 逐句 TTS → ffprobe/wave 实测样本数 → 标点停顿拼接 WAV
→ timeline.json（句/词精确起止）→ 帧数 = ceil(时长 × fps) → 渲染
```

- 每句单独合成，停顿由脚本按标点插入，用 WAV 采样数计算，误差为 0。
- 停顿策略：句末 `。！？：` 后 **350ms**；句中 `，；、—` 后 **120ms**；其他 **30ms**；场景末尾额外 **600ms** 留白。
- Bookmark（句边界）只能放在分句/分句末，句中切断会破坏语调。
- edge-tts 的 `WordBoundary` 事件 offset/duration 单位是 100ns，除以 1e7 得秒；用于逐词字幕高亮。
- 绝不按字数估时长；`duration_hint` 只是设计参考。

## 2. 旁白文案（最有效的"去机器味"手段）

TTS 再强也念不好书面长句。卡点 2 写文案时遵守：

- 一句一个信息点，中文短句，每句 ≤20 字为宜，单镜 ≤3 句。
- 先比喻后术语："它像一个只能从头翻的通讯录，这就是链表。"
- 避免长定语堆叠："一个用于在没有随机访问能力的数据结构中进行线性查找的过程" → "链表不能随机访问，只能一个一个找。"
- 数字带单位读出来（"八次比较"，不要写 `8 cmp`）。
- 中英混排时，英文缩写首次出现给出中文读法提示（写进 lexicon）。
- 句末用明确标点；脚本依赖标点决定停顿。

### 2.1 时长预算（在卡点 2 就算清，避免 QA 后返工）

实测 `zh-CN-YunxiNeural` 中文讲解约 **3.0~3.5 字/秒**；加上标点停顿后，单镜时长可粗算为：

```
预估秒数 ≈ 总字数 ÷ 3.2 + 句数 × 0.35 + 场景留白(默认 0.3~0.6s)
```

要让单镜满足 ≤10 秒的规范，**三句总字数建议 ≤26 字**（含标点），单句 ≤10 字。写 `storyboard.json` 时先用上式估算；不要等 `qa_scene.py` 报 `long-shot` 才回头精简文案——那会强制重新配音并重排帧号。需要更长留白时，用 scene 级 `scene_tail_ms` 覆盖全局值，而不是堆长句子。

## 3. lexicon.json：读音修正

在送 TTS 前做文本替换，字幕保留原文：

```json
{
  "RAG": "R A G",
  "HashMap": "Hash Map",
  "O(n)": "O n",
  "JVM": "J V M",
  "红黑树": "红黑树"
}
```

多音字可用同音字替换（如"重"读 chóng 时替换成"虫"仅在 TTS 文本中）。每次改 lexicon 都要重新生成 timeline（缓存按 text+voice+rate+pitch 哈希）。

## 4. 音色与升档

默认 edge-tts（免费、词级边界可用）。卡点 3 用 `--audition` 生成 2~3 个音色试听，再定稿：

| 音色 | 特点 | 适用 |
|---|---|---|
| `zh-CN-YunxiNeural` | 年轻男声、口语感 | 默认讲解 |
| `zh-CN-XiaoxiaoNeural` | 温和女声 | 通用、亲和 |
| `zh-CN-YunyangNeural` | 新闻男声、稳重 | 正式主题 |
| `zh-CN-XiaoyiNeural` | 活泼女声 | 轻快主题 |

升档（环境变量只在需要时设置，不得静默启用）：

```bash
# Azure 神经语音：支持 narration-relaxed / cheerful 等 style，中文自然度更高
export AZURE_SPEECH_KEY="..."
export AZURE_REGION="eastasia"

# ElevenLabs：多语种 v2，情感表现最强（需网络可达）
export ELEVENLABS_API_KEY="..."
```
设置后运行 `tts_generate.py --provider azure|elevenlabs`。两者仍逐句合成、输出同格式 timeline（词级边界为空时字幕按整句显示）。本地高质量方案（CosyVoice 等）可通过实现同样的 provider 接口接入。

## 5. 参数护栏与故障排查

| 症状 | 优先处理顺序 | 不要做 |
|---|---|---|
| 人机味重 | 换音色 → 加大停顿（350→450ms）→ pitch ±2Hz | 不要降速到 −10% 以下 |
| 语速太快 | 精简文案 / 增加场景留白 | 不要 rate < −5% |
| 语速太慢拖沓 | rate +5%~+8% | 不要靠删停顿解决 |
| 术语读错 | 改 lexicon.json 后重新生成 | 不要改字幕原文去迁就 TTS |
| 句间突兀 | 检查句末标点与停顿策略 | 不要整段一次性合成 |
| 音量忽大忽小 | 由 compose_video.py 统一 loudnorm | 不要逐句单独 normalization |

- `rate` 护栏 `[-5%, +8%]`，`pitch` 护栏 `[-2Hz, +2Hz]`。
- 成片统一响度：**−16 LUFS 集成 / −1.5 dBTP 峰值**，配 highpass 80Hz 去低频轰鸣。
- 有 BGM 时用 `--bgm`，音量压在旁白下约 20dB；没有就保持纯旁白，不要硬加音乐。

## 6. 字幕

- 字幕由 Canvas 运行时按 timeline 自动绘制：句子起点 = 真实音频起点；有词边界时逐词高亮。
- 长句（>20 字）在卡点 2 就拆成两句，不要在后期硬切。
- 字幕位置固定在底部安全区，字号 `caption_px`（默认 30），半透明深色底衬保证对比。
- 校对方式：播放成片，对照 `audio/timeline.json` 检查字幕起止；`qa/report.json` 会列出每句的时间。
