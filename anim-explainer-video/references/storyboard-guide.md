# 分镜设计指南（Stage 2 必读）

本指南约束 design.md 的分镜脚本质量。目标是：观众在零准备状态下，看完 3~5 分钟能复述主题的核心机制。

## 1. 叙事结构模板

标准四段式（总时长按比例分配）：

| 段落 | 占比 | 内容 | 典型分镜数 |
|---|---|---|---|
| 引入 | 10~15% | 抛出问题/场景（如"链表查找太慢了怎么办？"），展示封面标题 | 1 |
| 铺垫 | 20~25% | 讲清前置概念（链表的结构、查找 O(n) 的痛点），为机制做铺垫 | 2~3 |
| 核心机制 | 50~60% | 逐步展示主题过程本身，这是视频主体，分镜最细 | 4~7 |
| 总结 | 10% | 回顾要点、对比前后状态（如性能对比表格）、一句话结论 | 1~2 |

核心机制段落必须**按时间/步骤顺序**推进，每一步对应一个分镜，禁止一步讲多个变化。

## 2. 信息密度规则

- 每个分镜只引入 **1 个新概念**；已有元素可复用（如链表节点在后续分镜中继续存在）。
- 单帧画面上最多同时出现：1 个主图 + 1 段代码（≤6 行）+ 3~5 条标注文字。超出则拆分镜。
- 每段旁白 **2~3 句、40~90 字**，超过 90 字必须拆分。
- 讲解型动画常见误区（必须避免）：
  - 全部内容一帧堆完，靠观众暂停理解——不行，必须靠动画逐步呈现。
  - 只放静态图不动——每个分镜至少要有一个动画变化（元素出现/移动/变色/连线）。
  - 代码与图形脱节——讲到代码第 X 行时，图形上对应的部分必须同时高亮。

## 3. 旁白写法

- 口语化、短句，避免书面长句；先说结论再解释。
- 与画面的同步规则：旁白中每个关键名词出现时，画面上该元素应已出现或正在出现。
- 字幕 = 旁白原文（可微调标点），逐镜对应，写进 design.md 的字幕方案一节。

## 4. 动画效果词汇表（写入分镜时用统一术语）

- `appear`：元素淡入/弹出
- `move`：元素从 A 位移到 B（如指针移动）
- `highlight`：描边变色/加粗，用于强调当前关注对象
- `trace`：逐行/逐个依次显示（代码行、节点序列）
- `connect`：两点间画线（如建立父子链接）
- `recolor`：节点变色（如红黑树换色）
- `layout`：整组元素重新排布（如树旋转、rebalance）

转场仅用三种：`fade`（默认）、`slide-left`（推进感，用于步骤递进）、`hard-cut`（同一对象的连续动作内不用转场）。

## 5. 视觉风格规范

- 背景：深色（如 #0F172A）或浅色（如 #F8FAFC）二选一，全片统一；深色更适合代码主题。
- 主色/强调色/警示色各一个，给具体 hex；代码面板用等宽字体（Cascadia Code / JetBrains Mono，系统缺字体则用 Consolas 回退）。
- 节点圆角矩形直径 ≥ 90px（1080p 下），文字 ≥ 28px，保证手机端可读。
- 安全边距：四周留 80px；字幕固定在底部 60px 处，主图避开该区域。

## 6. design.md 分镜条目格式（严格遵守）

```markdown
### Scene 03 — 链表查找 O(n)
- 画面：7 个节点从左到右排开，指针从 head 逐个移动到第 5 个节点，已访问节点变灰
- 旁白：链表查找必须从头开始，一个一个往后找。如果目标在末尾，就要走完整个链表。
- 时长：待配音后确定（预估 15s）
- 动画：trace(节点1..5) → move(指针) → highlight(目标节点)
- 转场：fade
- 字幕：链表查找必须从头开始，一个一个往后找。如果目标在末尾，就要走完整个链表。
```

时长一律写"待配音后确定（预估 Xs）"，最终以 durations.json 为准。
