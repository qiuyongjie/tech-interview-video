# 视觉设计与运动规范

目标：看起来像"请了设计师"，而不是"PPT 自动播放"。好坏不靠审美口号，靠下面这些可执行判据 + `examples` 的正反例对照思路。

## 1. 语义色板

一种颜色只有一个含义，全片不变；分类实体（节点 A/节点 B、线程/进程）各自固定颜色，且不与角色色复用。

| 角色 | 默认色 | 含义 |
|---|---|---|
| `bg` | `#0B1020` | 背景（深蓝黑，护眼且对比度高） |
| `surface` | `#151D33` | 卡片/面板底 |
| `text` | `#E8EDF7` | 屏上文字 |
| `muted` | `#8A94A8` | 非焦点上下文 |
| `entity` | `#4CC9F0` | 主要对象（节点、数据项） |
| `focus` | `#FFD166` | 当前讲解对象（高亮） |
| `relation` | `#6B7A99` | 箭头、连线、坐标轴 |
| `good` | `#06D6A0` | 正确/更优 |
| `bad` | `#EF476F` | 错误/被淘汰 |
| `assumption` | `#B388FF` | 假设、未观测 |
| `quantity` | `#F6C85F` | 数字与量级 |

换主题时可调整具体 hex，但必须保持"角色 → 含义"映射，并写进 `style_tokens`。避免同时出现 3 种以上高饱和强调色。

## 2. 字体与版式

| 层级 | 像素 | 用途 |
|---|---|---|
| 标题 | 64 | 封面、章节卡 |
| 小标题 | 44 | 场景主标题 |
| 正文 | 34 | 主要解释文字 |
| 标签 | 26 | 节点标签、注释 |
| 字幕 | 30 | 底部字幕 |

- 中文用 `Microsoft YaHei`（已本机验证存在），代码/符号用 `Consolas`；每个字体族都要在 HTML 模板里声明 `@font-face` 或本地族名，`document.fonts.ready` 后再截帧。
- 安全边距：左右 ≥96px，上方 ≥120px，字幕区下方预留 180px。文字永不贴边。
- 一屏最多 7 个元素；超过就拆镜。正文行宽不超过屏宽的 65%。
- `focus` 色一屏只给一个对象；人人高亮等于没人高亮。

## 3. 运动（决定"贵不贵"的部分）

黄金规则：**快进慢出**。默认用 `easeOutCubic`，不要线性位移。

| 场景 | 时长 | 缓动 |
|---|---|---|
| 元素入场 | 225~300ms | `outCubic` / `outBack(1.7)` |
| 元素退场 | 180~240ms | `inCubic` |
| 状态切换/高亮 | 300ms | `inOutCubic` |
| 位置/形变 | 400~600ms | `outCubic` |
| 场景转场 | 默认 350ms | 合成器 `xfade` 交叉溶解；可选 slideleft/wipeleft；**不要**在场景脚本里再做整屏淡入淡出 |
| 顿悟揭示 | 500~700ms | `outExpo`，随后停 1~2 秒 |

- **持续运动层**（运行时强制）：每个场景都有缓慢推拉（scale 1.035±0.02）、微位移（±22px）、视差点阵与全高柔和扫描光；字幕层独立绘制保持稳定。目的是消除"画面定住、像 PPT"的感觉。
- **动效避让红线**：装饰元素不得穿越正文文字，不得进入字幕安全区；扫光必须使用贯穿容器全高的柔和渐变（透明度 ≤0.10），禁止用固定高度 `fillRect` 制造可见矩形色块；弧线/圆环的圆心与半径必须避开文字区域。实例：曾在 statement 镜用 `fillRect(..., 330, 400, 340)` + 0.22 alpha 形成棕黄硬边色块，并用圆心在文字处的同心弧穿过标题——两者都必须禁止。
- **节拍变化**：一个场景内至少 2~3 次视觉状态变化（焦点切换、数值滚动、高亮行移动、构图缩放），用 `S.n(cueId)` 或 `t` 分段驱动，不要 reveal 完就静止。
- **Stagger**：并列元素依次入场，间隔 60~100ms（像多米诺），不是同一帧全部弹出。
- 关键帧间距即速度：越紧越快；线性只用于匀速进度条/扫描线。
- 动画必须解释状态变化（节点移动、指针跳转、数据变换），不要为了"画面在动"而抖动装饰。
- 每个 claim 出现后至少留 1 秒静态时间让观众消化；一镜旁白不超过 10 秒。
- 运动预算分级：L1 微交互（高亮、颜色）→ L2 元素级（位移、缩放）→ L3 场景级（镜头推拉、转场）。一镜最多用一次 L3。

## 4. 镜头配方

| 镜头类型 | 做法 |
|---|---|
| 开场钩 | 一个反常识问题/生活比喻，配一个视觉锚点；不要"大家好今天我们来讲" |
| 定义镜 | 术语出现前先给比喻；术语用 focus 色，定义文字用 text 色 |
| 机制镜 | 流程节点逐个出现，箭头跟随解说依次画出；用同一组坐标保持一致 |
| 对比镜 | 左右分屏，旧方案 muted/red，新方案 focus/green，最后给数字结论 |
| 数据镜 | 数字用 `quantity` 金，带单位；数字变化用滚动，不用淡入替换 |
| 顿悟镜 | 前面积累的元素在这一镜合并成一个结论，慢速 reveal + 留白 |
| 收尾镜 | 一句话总结 + 三个关键词回扣，不用"感谢观看" |

## 5. 正反例判据（把"好看"变成可检查项）

| 维度 | Good | Bad |
|---|---|---|
| 主体尺寸 | 主体占屏宽 40%~70%，一眼可辨 | 主体缩在角落或铺满全屏无留白 |
| 大字 | 关键数字/术语单独放大，周围留空 | 满屏大字与正文抢注意力 |
| 留白 | 背景有 30% 以上呼吸空间 | 元素塞满、到处都是框 |
| 高亮 | 一屏仅一个 focus 对象 | 多个元素同时高亮 |
| 文字 | 短句分行，行距 ≥1.4 | 长句挤成一行、贴边或压在图形上 |
| 配色 | 语义色 ≤3 种，其余 muted | 彩虹色、相邻高饱和色打架 |
| 节奏 | 动完有停顿 | 全程匀速动画、没有静止点 |
| 转场 | 淡入淡出 + 位移，300~500ms | 硬切或花哨翻转 |

## 6. 图片使用红线

- AI 生图**仅限**封面、章节氛围、背景纹理；不得用来画数据结构状态、数值、流程图（会画错且不可复现）。
- 背景纹理需低对比（透明度 ≤15%），不能压低正文可读性。
- 数据结构、状态变化、代码、图表一律 Canvas 程序化绘制。

## 7. 交付前视觉自检

- [ ] 关键帧中每个 claim 都有对应画面证据（旁白与画面数值一致）
- [ ] 无文字越界、无文字互相覆盖、字与连线无交叉
- [ ] 一屏 ≤7 元素、≤3 种高饱和色、仅 1 个焦点
- [ ] 字幕在安全区内，逐词高亮与音频边界对齐
- [ ] contact sheet 逐镜看一遍，节奏有动静交替
