# tech-interview-video v2.2：技术面试题讲解视频生成（动画版 / 图文结合 / 开场白 + 字幕）

本 Skill 将任意技术主题的面试题转化为四件交付物：`outline.md`（大纲）、`slides.pptx`（图文分层 PPT）、`subtitles.srt`（字幕文件）、`video.mp4`（1080p 逐条动画讲解视频 + 开场白 + 独立结束语，默认烧录字幕）。所有输出文件放置在当前工作目录的 `tech-interview-video-output/` 文件夹下。

## 版本历史

- **v1.0**：固定可爱风格、3–5 页、静态翻页视频。
- **v2.0**：① PPT 内容逐元素分步呈现，视频输出逐条渐入动画；② 页数按主题与内容量灵活决定，保证覆盖完整；③ 新增独立结束语（总结 + 收尾画面）；④ 风格不固定，改为"风格档案"机制，核心约束为风格与主题强相关、内容完整。
- **v2.1**：① **图文结合**：每个内容页必须包含至少一个图形化元素（流程图、架构图、对比卡片、数据大字、表格等，用形状实际绘制而非文字罗列），严禁整页纯文字要点；② 大纲阶段为每页设计"图示方案"，PPT 阶段用形状实际绘制，图示同样参与动画分层。
- **v2.2（当前）**：① **独立开场白（必须）**：视频以独立开场白页开篇（问候 + 主题引入 + 内容预告），大纲与 PPT 同步增加开篇页；② **字幕默认烧录**：视频必须配有与配音逐句对齐的字幕（同时输出 `subtitles.srt`），字幕必须逐字校对，确保准确无误、无错别字。

## 硬性规则（必须遵守，严禁跳过）

1. **严禁跳过任何阶段**：三个阶段必须按顺序执行，每个阶段的产物必须实际生成到磁盘。
2. **严禁跳过人工审核点**：在进入阶段二（生成 PPT）之前，必须暂停并等待用户回复"确认"字样。用户未回复"确认"时，**绝对禁止**继续生成 PPT 或视频，即使任务看起来已完成。
3. **严禁凭记忆回答版本相关问题**：所有涉及语言/框架版本特性、API 行为的内容，必须联网搜索核实并标注来源。
4. **必须等待用户输入**：任何"暂停机制"都意味着停止生成、输出审核请求文本、结束当前回合，等待用户下一条消息。
5. **风格必须与主题强相关**：严禁无依据地套用风格；所选风格的配色、字体、装饰必须能从主题推导出理由，并在交付时说明。
6. **内容必须完整**：大纲必须覆盖用户提供的全部题目/知识点，严禁为控制页数而删减内容，也严禁为凑页数而注水。
7. **图文结合必须执行（v2.1 新增）**：除标题页与结束语页外，**每个内容页必须包含至少一个图形化元素**（流程图、架构图、对比卡片、时序图、数据大字、表格、代码高亮块等，用形状实际绘制而非文字罗列），严禁整页只有要点文字。图示与文字配比建议：图示占页面视觉面积 ≥ 40%。
8. **字幕必须准确无误（v2.2 新增）**：视频必须配有字幕（默认烧录进画面，同时输出 `subtitles.srt` 字幕文件）。字幕文本必须与讲解文案**逐字一致**，交付前必须**逐句校对**（检查错别字、标点、专有名词/术语拼写、大小写），**严禁出现任何错别字**；校对结果须在交付时说明。

## 第 0 步：前置检查

1. **识别技术领域**：判断主题属于哪个技术领域。主题不明确时，向用户确认目标领域与题量。
2. **面试题目**：确认面试题清单（用户提供的文件/列表，或确认"由 AI 推荐高频题"）。
3. **参考资料**：确认用户是否提供参考资料；无则以联网搜索结果为准。
4. **风格选择**：风格不固定。默认由 AI 依据主题从"风格档案"中推荐一种并给出理由；用户已指定风格（如"可爱风格"）则直接采用；也可自定义风格档案。必须在此步确定最终风格。
5. **输出确认**：复述交付文件（`outline.md`、`slides.pptx`、`video.mp4`）、输出目录、预估页数与所选风格，得到用户默许或"确认"后进入阶段一。

## 阶段一：资料收集与大纲生成

1. **必须联网搜索**：使用 web_search / web_fetch 核实每道题的最新准确解释，禁止仅凭训练记忆作答。
2. **标注来源**：所有版本相关内容必须标注来源链接与版本号。
3. **页数灵活决定**：页数由主题与内容量推导，推荐公式：**开场白页 1 页（v2.2 必须，问候 + 主题引入 + 内容预告，兼作开篇导入）** + 每道题 1–2 页（视信息量）+ 总结页 1 页 + **结束语页 1 页（独立收尾画面）**；典型范围 6–16 页。
4. **完整性自检（必须执行并在大纲末尾列出核对结果）**：逐条核对题目全覆盖无遗漏、无重复注水、每页要点不超过 3 条、每个内容页均有图示方案。
5. **生成 `outline.md`**：沿用通用四段式结构（页标题 / 核心要点 / 示例代码要点 / 来源标注）；对每页额外标注**图示方案**与**呈现顺序**（见下条）；开场白页需在大纲中写明**开场白文案**（40–60 字：问候语 + 本次主题 + 内容结构预告）。
6. **图示方案设计（v2.1 新增，每页必填）**：在大纲中为每个内容页明确标注一个图示类型与内容草稿，供阶段二绘制。图示类型选型参考：

   | 内容特征 | 推荐图示类型 | 图示要点 |
   |----------|--------------|----------|
   | 流程/生命周期/请求链路 | 流程图 | 圆角矩形节点 + 箭头连接线，关键步骤配色强调 |
   | 架构/模块划分/分层 | 架构框图 | 分层容器 + 子模块卡片，标注数据流向 |
   | 多对象交互/调用 | 时序图 | 生命线 + 水平箭头，编号标注步骤顺序 |
   | 概念对比（如 A vs B） | 对比双卡片 | 左右分栏卡片，逐项对齐比较，差异点高亮 |
   | 性能/量化指标 | 数据大字 | 2–3 个大号数字指标卡（如 QPS、耗时），配简短说明 |
   | 分类/枚举/清单 | 图标卡片网格 | 2×2 或 1×3 卡片，每卡配一个图标/emoji + 短语 |
   | 代码题/原理题 | 代码高亮块 + 标注 | 代码块中用颜色高亮关键行，旁边配箭头标注 |
   | 状态变迁（如线程状态、事务状态） | 状态机图 | 圆形/圆角状态节点 + 带标签的转移箭头 |

   示例标注格式：`图示：流程图（Client → Registry → Service → DB，Registry 节点用主色强调）`。
6. **输出大纲**：写入 `tech-interview-video-output/`，并在回复中完整展示。

## ★ 人工审核点（强制暂停）

输出 `outline.md` 后，**必须停止**，输出以下话术并结束回合：

> 以上是 PPT 大纲（共 X 页，主题：XX，风格：XX 及理由）。请审阅。回复"确认"后我将开始生成 PPT（slides.pptx）并进入动画视频合成阶段；回复修改意见则我先调整大纲。

**在用户回复"确认"之前，严禁进入阶段二。** 严禁自行推断用户已同意、严禁在等待时提前生成 PPT 内容。

## 阶段二：生成 PPT（用户回复"确认"之后才执行）

### 1. 风格档案（必须使用阶段一确定的档案）

风格定义为"档案"：一张包含配色表、字体表、装饰元素、适用主题的表。内置示例：

| 档案 | 配色示例 | 字体 | 装饰 | 适用主题 |
|------|----------|------|------|----------|
| 可爱风 | 奶油白 `#FFF9F4` 底、樱花粉 `#F8A5C2`、薄荷绿 `#B5EAD7`、淡雾紫 `#C7CEEA`、奶油黄 `#FFE9A8`、正文深灰棕 `#5B5457`、代码底浅奶咖 `#FFF3E2` | 标题/正文圆体（幼圆等）≥32/20pt，代码等宽 ≥16pt | 虚线圆角卡片、贴纸 emoji（每页 1–2 个）、爱心星星点缀、顶部波浪色带 | 入门科普、轻松向内容 |
| 深色科技风 | 深空底 `#0F172A`、主色青 `#22D3EE`、辅助紫 `#A78BFA`、正文 `#E2E8F0`、代码底 `#1E293B` | 无衬线粗标题 + 等宽代码 | 细网格线、发光边框、进度点 | 系统架构、底层原理 |
| 商务简报风 | 白底、藏蓝 `#1E2761`、金色点缀 | 衬线标题 + 无衬线正文 | 单侧粗边框、数据大字 | 企业级工具、数据库 |

- 扩展规则：新增风格只需新增一个档案表并在第 0 步"风格选择"中登记；阶段一/三流程不变。
- 对比度硬性要求：正文与背景 ≥ 4.5:1，标题 ≥ 3:1；图示节点填充与节点文字同样需满足对比度要求。
- 版式通用要求：标题 ≥ 32pt、要点 ≥ 20pt、图示节点文字 ≥ 16pt、代码 ≥ 16pt；每页不超过 3 个要点；页数与 `outline.md` 完全一致。

### 2. 图示绘制（v2.1 核心要求，必须执行）

按阶段一大纲中每页标注的**图示方案**，用 python-pptx 的**原生形状**实际绘制图形（严禁用整段文字代替图示）：

1. **常用图形元素**：
   - 节点/卡片：`MSO_SHAPE.ROUNDED_RECTANGLE`（圆角矩形），加填充色、边框色与阴影；
   - 连接线/箭头：`MSO_CONNECTOR.STRAIGHT` 或 `MSO_SHAPE.RIGHT_ARROW`，箭头上可叠加小号文字标签（如"提交""回滚"）；
   - 分组/分层容器：`MSO_SHAPE.ROUNDED_RECTANGLE` 半透明浅色底，内嵌子卡片；
   - 徽章/序号：`MSO_SHAPE.OVAL` 小圆 + 白字数字（①②③），用于标注步骤顺序；
   - 高亮强调：关键节点用风格主色填充 + 加粗描边，其余节点用弱化灰/浅色，形成视觉焦点。
2. **绘制规范**：
   - 每个图示先用纸面坐标规划（区域约起于标题下方，占页面 ≥ 40% 高度），节点间距均匀、箭头不与文字重叠；
   - 图示节点内文字精炼为 2–6 字短语，详细解释放左侧要点文字，图文分工："要点讲是什么，图示讲怎么流转"；
   - 代码类页面：代码底色块 + 关键行用主色高亮 + 侧边箭头标注指向关键行；
   - 图示整体作为一组形状，**每个节点/卡片/箭头独立命名**（见下方分层规范），使其也能逐元素渐入。
3. **典型版式参考**（可按内容组合）：
   - 左文右图：左侧 35% 放要点文字，右侧 65% 放流程图/架构图；
   - 上要点下图示：顶部一行要点，下方主图；
   - 全幅图示页：对比卡片、状态机等以图为主体，仅顶部保留一句引导语。

### 3. 元素分层（动画的前提，必须执行）

生成 PPT 时必须将每页元素按**呈现顺序**命名（python-pptx 中设置 `shape.name`）：

- 命名规范：`L0_title`（标题层）→ `L1_p1`、`L1_p2`…（要点层，每条一个形状）→ `L2_d1`、`L2_d2`…（图示层：节点/卡片/箭头逐个命名，按逻辑顺序渐入）→ `L2_code`（代码层）→ `L3_deco`（装饰层，随页淡入可忽略）。
- 图示绘制顺序即渐入顺序：一般按"容器 → 节点 → 箭头/标签"或"从左到右、从上到下"编号。
- 同一呈现阶段的元素使用同一层号。此命名是阶段三生成动画帧的依据，**严禁省略**。

### 4. 生成工具与 QA

1. 优先使用 `pptx` Skill；否则用 Python + `python-pptx`（虚线枚举在 `pptx.enum.dml.MSO_LINE_DASH_STYLE`；中文字体需同时设置 `a:ea` typeface）。
2. 生成后必须导出为图片做视觉 QA（文字溢出、元素重叠、低对比度、**图示箭头错位/节点文字溢出**），必须修复并复验至少一轮。
3. **输出 `slides.pptx`** 到 `tech-interview-video-output/`。

## 阶段三：动画视频合成

1. **备注文案**：为每页撰写 60–100 字口语化讲解文案，写入演讲者备注，并按该页呈现阶段**切分为分句**（每阶段一句，供动画与字幕对齐）。
2. **开场白（v2.2 必须）**：视频以第一页开场白页开篇，配音为大纲中确定的**开场白文案**（问候语 + 本次主题 + 内容结构预告，40–60 字）；画面为标题页 + 主题信息（或简洁引导图示），开场白配音播完后进入正式内容页。
3. **逐条动画帧生成（核心）**：将每页拆为 K 个呈现阶段（标题 → 要点逐条 → 图示逐节点/箭头 → 代码），生成 K 张累计 PNG：
   - 方法 A（推荐，与 pptx 完全一致）：加载 `slides.pptx` 副本，按 `shape.name` 删除"未呈现"的形状，另存临时 pptx 后用 PowerPoint/WPS COM 导出 1920×1080 PNG；每个阶段一张。
   - 方法 B（无 Office 环境）：用 PIL 按同一版式参数渐进绘制各阶段帧。
   - 注意：COM 导出后 `wpp.exe`/`POWERPNT.exe` 可能锁住文件，按启动时间只结束本次实例后再重写文件；严禁删除用户文件解锁。
4. **动画合成**：用 ffmpeg `xfade`（`transition=fade`，0.4–0.6s）将各阶段帧串联，形成"元素依次渐入"；每个阶段的停留时长 = 对应分句配音时长 + 0.5s。多段 xfade 需按 offset 累计构建滤镜链。
5. **结束语（必须）**：最后一页为独立结束语页（总结要点 + "感谢观看/完"收尾画面），配音为收尾话术，画面静置 2–3 秒后淡出黑场结束。
6. **字幕生成与校对（v2.2 必须，与配音版/降级版均适用）**：
   - 依据每页分句文案生成 `subtitles.srt`：每条字幕对应一个分句，起止时间与该分句配音（或画面停留）严格对齐；
   - 字幕样式：字号适中（建议 44–52px）、白字黑边或半透明底条、位于画面底部安全区内，不遮挡图示与代码；
   - **逐句校对（硬性要求）**：生成后将全部字幕文本逐句与讲解文案比对，检查错别字、标点、专有名词与术语拼写（如 Seata、Raft、Dubbo 等），**零错别字后才允许烧录**；
   - 烧录：用 ffmpeg `subtitles` 滤镜（libass）将字幕烧录进最终视频。
7. **音色选择**：edge-tts 音色随风格档案配置——默认 `zh-CN-XiaoxiaoNeural`（晓晓，温和女声，适合可爱风）；深色科技风/商务简报风推荐 `zh-CN-YunxiNeural`（云希，阳光男声）或 `zh-CN-YunjianNeural`（云健，浑厚男声）；用户明确指定音色时以用户为准。全部音色用 `edge-tts --list-voices` 查看，可用 `rate="+15%"` 等调节语速；音色在交付时说明。
8. **TTS 与降级**：推荐 `edge-tts` 生成每分句配音 mp3；若 TTS 不可用，必须明确告知用户，降级生成**无配音 + 内嵌字幕**版本（各阶段帧上叠加对应分句字幕，每阶段停留 ≥ 3s），严禁因缺少 TTS 中止任务；降级版字幕同样执行第 6 条校对要求。
9. **输出 `video.mp4`**：1920×1080，H.264 + AAC（降级版无音频轨），默认含烧录字幕；同时输出 `subtitles.srt`，一并写入 `tech-interview-video-output/`。

## 输出规范（最终交付）

| 文件 | 要求 |
|------|------|
| `outline.md` | 页数按内容量灵活决定；含**开场白文案**、完整性自检结果与来源标注；每页标注**图示方案**与呈现顺序 |
| `slides.pptx` | 风格与主题强相关；**每个内容页含至少一个形状绘制的图示**；元素按 `L{层}_{名称}` 命名分层；每页 ≤3 要点 |
| `subtitles.srt` | 每条字幕对应一个分句、与配音/画面停留对齐；**逐句校对后零错别字** |
| `video.mp4` | 1080p，逐条渐入动画（含图示逐节点渐入）；**以开场白页开篇**；默认烧录校对后的字幕；每页备注 60–100 字文案（或无配音+字幕版）；**含独立结束语与收尾画面** |

最后向用户汇报文件绝对路径、所选风格及理由，并提示可用播放器验证动画效果。

## 通用化设计要求（领域解耦）

1. **内容结构通用**：大纲四段式结构（页标题/要点/图示方案/代码要点/来源）与领域无关。
2. **主题适配点仅三处**：搜索关键词（阶段一）、代码示例语言、风格档案选择（阶段二），其余流程一致。
3. **风格即配置**：风格以档案表形式扩展，新增风格不影响既有流程；图示配色取自当前风格档案，任何风格下均适用。
4. **动画即分层**：任何风格下，只要形状按 `L{层}_{名称}` 命名（含图示节点 `L2_d{n}`），阶段三动画管线即可复用。
5. **开场白与字幕即模板**：开场白文案结构（问候 + 主题 + 内容预告）与字幕生成/校对流程与领域无关，任何主题下流程一致。
