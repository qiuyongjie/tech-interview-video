# tech-interview-video：技术面试题可爱风格讲解视频生成

本 Skill 将任意技术主题的面试题转化为三件交付物：`outline.md`（大纲）、`slides.pptx`（可爱风格 PPT）、`video.mp4`（1080p 讲解视频）。所有输出文件放置在当前工作目录的 `tech-interview-video-output/` 文件夹下。

## 硬性规则（必须遵守，严禁跳过）

1. **严禁跳过任何阶段**：三个阶段必须按顺序执行，每个阶段的产物必须实际生成到磁盘。
2. **严禁跳过人工审核点**：在进入阶段二（生成 PPT）之前，必须暂停并等待用户回复"确认"字样。用户未回复"确认"时，**绝对禁止**继续生成 PPT 或视频，即使任务看起来已完成。
3. **严禁凭记忆回答版本相关问题**：所有涉及语言/框架版本特性、API 行为的内容，必须联网搜索核实并标注来源。
4. **必须等待用户输入**：任何"暂停机制"都意味着停止生成、输出审核请求文本、结束当前回合，等待用户下一条消息。
5. **必须遵循可爱风格规范**：所有 PPT 页面必须符合下方"可爱风格视觉规范"，严禁混用其他风格元素。

## 第 0 步：前置检查

在开始任何阶段之前，逐项确认：

1. **识别技术领域**：判断主题属于哪个技术领域（如 Java、Python、Go、React、Docker、Kubernetes、MySQL 等）。主题不明确时，向用户确认目标领域与题量（默认 10 题）。
2. **面试题目**：向用户确认面试题清单。若用户已提供文件（如 `questions.md`、题目列表），读取并复述题目数量与范围；若未提供，先询问题目或确认"由 AI 推荐该领域高频面试题"。
3. **参考资料**：确认用户是否提供参考资料（笔记、文档、代码）。无参考资料时以联网搜索结果为准。
4. **风格确认**：默认使用"可爱风格"。若用户要求其他风格，需在阶段二前明确其视觉要素，其余流程不变。
5. **输出确认**：复述本次将交付的文件（`outline.md`、`slides.pptx`、`video.mp4`）与输出目录，得到用户默许或"确认"后进入阶段一。

## 阶段一：资料收集与大纲生成

1. **必须联网搜索**：使用 web_search / web_fetch 工具搜索每道题的最新准确解释（官方文档、权威博客、规范原文），搜索时使用该技术领域的准确关键词。禁止仅凭训练记忆作答。
2. **标注来源**：所有版本相关内容（如"JDK 17 起""React 18 变化"）必须在大纲中标注来源链接与版本号。
3. **生成 `outline.md`**：3–5 页的大纲，每页对应一道或多道题，统一使用以下通用结构（与领域解耦，可复用于任何技术主题）：
   - 页标题
   - 核心要点（每页不超过 3 条）
   - 示例代码要点（使用该主题对应语言的语法）
   - 来源标注
4. **输出大纲**：将 `outline.md` 写入 `tech-interview-video-output/` 目录，并在回复中完整展示大纲内容。

## ★ 人工审核点（强制暂停）

输出 `outline.md` 后，**必须停止**，输出以下格式的话术并结束回合：

> 以上是 PPT 大纲（共 X 页，主题：XX 技术，风格：可爱风格）。请审阅。回复"确认"后我将开始生成 PPT（slides.pptx）并进入视频合成阶段；回复修改意见则我先调整大纲。

**在用户回复"确认"之前，严禁进入阶段二。** 严禁自行推断用户已同意、严禁在等待时提前生成 PPT 内容。

## 阶段二：生成可爱风格 PPT（用户回复"确认"之后才执行）

### 可爱风格视觉规范（必须全部满足）

**1. 配色（柔和马卡龙色系）**

| 用途 | 颜色 | 色值 |
|------|------|------|
| 页面底色 | 奶油白 | `#FFF9F4` |
| 标题/强调主色 | 樱花粉 | `#F8A5C2` |
| 辅助色 1 | 薄荷绿 | `#B5EAD7` |
| 辅助色 2 | 淡雾紫 | `#C7CEEA` |
| 辅助色 3 | 奶油黄 | `#FFE9A8` |
| 正文文字 | 深灰棕（保证对比度） | `#5B5457` |
| 代码块底色 | 浅奶咖（圆角） | `#FFF3E2` |

- 对比度硬性要求：正文与背景对比度 ≥ 4.5:1，标题与背景 ≥ 3:1；禁止在浅色底上使用浅色文字。

**2. 字体**

- 标题：圆润字体（如"幼圆 / 思源圆体 / 华康圆体"），≥ 32pt。
- 正文：同款圆体，≥ 20pt。
- 代码：等宽字体（Cascadia Code / Consolas），≥ 16pt；关键字用樱花粉、字符串用薄荷绿深色变体（`#5FA98F`）、注释用灰棕，在浅奶咖底色圆角矩形内呈现。

**3. 图标**

- 每页 1–2 个贴纸风图标/emoji（如 🎀 ✨ 📌 🐱 ☁️ ⭐），置于标题旁或要点前，严禁堆砌超过 3 个。

**4. 装饰元素**

- 要点区使用圆角卡片（圆角矩形 + 虚线或细实线边框，可加柔和阴影）。
- 页角点缀云朵、星星、爱心等简单形状（小尺寸、低饱和，不遮挡内容）。
- 页面顶部可用波浪形或圆弧色带（樱花粉/薄荷绿交替）。

**5. 版式**

- 大字号原则不变：标题 ≥ 32pt，要点 ≥ 20pt，代码 ≥ 16pt。
- **每页不超过 3 个要点**，每要点置于独立圆角卡片内。
- 页数与 `outline.md` 一致；标题区固定于页面左上（图标 + 圆体标题），内容区居中偏下。

### 生成工具

1. 优先使用 `pptx` Skill；否则用 Python + `python-pptx`（`pip install python-pptx`）。
2. 圆角效果在 python-pptx 中使用 `ROUNDED_RECTANGLE` 形状实现；虚线边框枚举为 `from pptx.enum.dml import MSO_LINE_DASH_STYLE`（**严禁**使用不存在的 `pptx.enum.line`）；中文字体需同时设置 `a:ea` typeface 才生效；圆体字体缺失时回退到系统默认字体并在交付时说明。
3. **输出 `slides.pptx`** 到 `tech-interview-video-output/`。
4. 生成后必须导出为图片做视觉 QA（检查文字溢出、元素重叠、低对比度），发现问题是常态，必须修复并复验至少一轮。

## 阶段三：视频合成

1. **备注文案**：为每页幻灯片撰写 60–100 字的口语化讲解文案，写入该页演讲者备注（speaker notes）。
2. **TTS 与合成工具**：
   - 推荐：`edge-tts`（`pip install edge-tts`）生成每页配音 mp3；`ffmpeg`（需单独安装并加入 PATH）或 `moviepy`（`pip install moviepy`）合成。
   - 每页导出为 1920×1080 PNG，按"图片时长 = 配音时长 + 0.5s"拼接。Windows 无 LibreOffice 时，优先用 PowerPoint/WPS COM 导出：`New-Object -ComObject PowerPoint.Application` → `Presentations.Open(path, $true, $false, $false)` → `Export(dir, "PNG", 1920, 1080)`。
   - **文件锁注意**：COM 导出后 WPS/PowerPoint 进程可能仍占用 `slides.pptx`，必须先结束该进程（`wpp.exe` / `POWERPNT.exe`，按启动时间只结束本次实例）才能重写 PPT；严禁删除用户文件来解锁。
   - 视频分段参数参考：`ffmpeg -loop 1 -framerate 30 -i frame.png -i note.mp3 -filter_complex "[1:a]apad[a]" -t <配音时长+0.5> -vf scale=1920:1080... -c:v libx264 -pix_fmt yuv420p -c:a aac seg.mp4`，再用 concat demuxer 拼接。
3. **降级方案**：若当前环境不支持 TTS，必须明确告知用户，生成**无配音 + 内嵌字幕**版本（字幕即各页备注文案，使用 ffmpeg `subtitles` 滤镜烧录），严禁因缺少 TTS 而中止任务。
4. **输出 `video.mp4`**：分辨率 1920×1080（1080p），H.264 编码，写入 `tech-interview-video-output/`。

## 输出规范（最终交付）

完成后必须交付并逐一核对以下三个文件存在于 `tech-interview-video-output/`：

| 文件 | 要求 |
|------|------|
| `outline.md` | 3–5 页大纲，版本相关内容含来源标注 |
| `slides.pptx` | 可爱风格（马卡龙配色、圆角卡片、圆体字、贴纸图标、每页 ≤3 要点） |
| `video.mp4` | 1080p，每页备注 60–100 字口语化文案（或无配音+字幕版） |

最后向用户汇报文件绝对路径，并提示可用播放器验证。

## 通用化设计要求（领域解耦）

1. **内容结构通用**：`outline.md` 的四段式结构（页标题/要点/代码要点/来源）与技术领域无关，任何主题复用同一结构。
2. **主题适配**：领域差异只体现在两处——搜索关键词（阶段一）与代码示例语言（大纲和 PPT 中的代码块），其余流程与模板完全一致。
3. **风格即配置**：可爱风格的配色、字体、装饰定义为上方固定"视觉规范表"。未来扩展其他风格（如深色科技风、商务风）时，只需替换该表并新增一节风格规范，阶段一/三流程不受影响。
4. **扩展方式**：新增领域无需修改本 Skill；新增风格时在阶段二下新增"风格规范"小节，并在第 0 步"风格确认"中登记可选风格名。
